# Instrumentation audit (before replay)

- `frame_id` is server-issued and increases across resets; session version increments on reset. Browser associates the sole pending original canvas with the detection response. Native source is stretched to 640×480; crop x/y scales differ for 16:9 input. Mapping adds 8% each side and clamps.
- `video_timestamp` is `video.currentTime` read just before canvas capture. It is a media timeline position, not a wall-clock timestamp or guaranteed decoded-frame presentation timestamp.
- Browser diagnostic RTT begins before JPEG encoding, includes encoding, socket transport, server work and response delivery. Server `detect_ms` surrounds `model.track` only; it excludes JPEG decode, tracking/identification bookkeeping after `model.track`, and annotation encoding.
- Crop acknowledgment `ok` means accepted into the OCR per-track slot, **not** OCR completed. `blurry`, `too_small`, `oversized`, `throttled`, `complete`, `track_expired`, and other rejection reasons must be separated. Queue replacement and duplicate-image skipping do not constitute recognition failure.
- `request_to_receipt_ms` uses server monotonic timestamps from request creation to crop processing entry. It includes outbound response work, browser handling/encoding, return transport and socket queueing; it is not pure network latency.
- `queue_wait_ms` starts in `submit` and ends immediately before OCR prediction. It can include first-use OCR model startup, scheduling and image-hash work. It is not pure queue time. `ocr_ms` measures worker prediction round trip. Errors and duplicate skips may lack these timings.
- `jev.duration_ms` measures classify execution, including external HTTP and response validation. No Jev scheduler wait or per-request absolute start/finish is exported. `jev.lines` and `source_request_ids` identify accumulated evidence; only the latest associated outcome survives per crop, with replacement count.
- Browser export has no per-stage wall-clock timestamps and does not export detection RTT/model timings per frame. Status snapshots arrive approximately once per second and can miss short-lived states. `/api/ident-debug` times are relative to a base recomputed from active tracks; do not compare that base across snapshots without preserving it.
- Accepted/completed identification at confidence ≥0.70 freezes OCR for that track. This is a scheduler policy, not calibrated probability or exact-SKU verification. Generic/empty `needs_more_evidence` cannot distinguish no crop, rejection, queueing, duplicate suppression, empty OCR, Jev failure or an insufficient-evidence answer.
- 3840×2160 originals exceed the browser's 12 MiB raw-image check: every original PNG is omitted. Exact uploaded crops remain, subject to 60-request/24 MiB bounds. Original video reconstruction from `currentTime` is approximate unless a matching capture was preserved independently. Missing/evicted evidence will be labeled, not reconstructed as certainty.
- Reset uses ordered WebSocket acknowledgment and invalidates browser encoding callbacks. Backend resets packing, detector tracker, outstanding crops and identification. In-flight OCR uses evidence-object identity; Jev completion checks current evidence identity before applying. This is static-code evidence, not proof of absence of runtime races.
